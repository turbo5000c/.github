# Support

These repos are personal projects — experiments, PoCs, and tooling I've built for my own use and shared publicly. Support is best-effort, but I do genuinely try to help when I can.

---

## Getting help

### 1. Read the README first

Most repos have setup notes, prerequisites, and known caveats in the README. It's worth a read before opening an issue.

### 2. Search existing issues

Someone may have hit the same problem already. Check both open and closed issues.

### 3. Open an issue

If you're stuck and the README doesn't help, open an issue in the relevant repo. Include:

- **What you were trying to do**
- **What you expected to happen**
- **What actually happened** (error output, logs, etc.)
- **Your environment** (OS, tool versions, cloud provider, etc.)

The more detail you provide, the faster I can help.

---

## What I can help with

- Bugs in the code or configuration
- Unclear or missing documentation
- Getting a project running in a standard setup
- Understanding how something is supposed to work

## What's out of scope

- General DevOps consulting or architecture reviews
- Adapting a PoC to your specific production environment
- 24/7 support SLAs (this is a personal GitHub, not a managed service)
- Issues caused by unsupported or heavily modified forks

---

## Response times

I respond when I can. During busy periods, it might take a few days. If something is urgent or broken in a way that blocks you, say so in the issue — it helps with prioritisation.

---

## Community

There's no dedicated forum or chat for these projects. GitHub Issues is the right place for project-specific questions.

If you find something useful or end up building on it, I'd love to hear about it. Drop a comment or open an issue just to share — those are always welcome.
